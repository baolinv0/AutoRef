## 0. 结论边界与问题锚点

本计划能够验证：在预定义任务要求下，输出是否呈现更好的可观察细节、较少的可见内容损伤和更高的盲评使用价值。

本计划不能证明：新增纹理就是原场景真实纹理，无法读取的文字被正确还原，或不可辨认身份细节被准确恢复。人工共识、VLM 评分、输入一致性都不是缺失的 GT。

拟使用“约束下的感知细节改善”“可观察内容保持”“人工判定候选覆盖率”等表述，不使用“恢复真实高频”“正确纹理恢复率”“GT oracle”等表述。

先验证三项命题，不能相互替代：

1. 所测试简单方法是否已能满足需求，或仍存在可观察的细节—保真权衡。
2. 固定执行器时，改变 Harness 是否确实有改善空间。
3. 自动优化是否优于人工设计和等预算的较简单搜索。

## 2. 任务定义：先冻结什么叫“保真”

### 2.1 主任务：细节改善，保持影调与颜色

首轮聚焦一个任务：在既有曝光、白平衡、整体氛围及场景结构可接受的图像上，降低退化感、改善可见细节，同时尽量保持影调和颜色。避免将严重欠曝、必须改曝光才能恢复的样本混入主任务。

Tone/Color 的约束对象为输入图中需保留的低频影调、主要对象颜色、光源关系和氛围。约束不能简单等同于 RGB 均值、方差或直方图相同。

### 2.2 可选扩展：曝光或偏色本身需要恢复

单独定义低光／偏色任务，评价“是否达到目标照明和色彩”，不以接近输入色调为成功标准。分开标注、分开统计，不与主任务合并一个总分。

### 2.3 每图任务卡

在生成之前，由不看方法输出的人记录：图像 ID、场景组、任务意图、可观察内容、目标细节区域、稳定颜色／影调锚点、高风险文字／人脸／物体区域，以及无法确认的信息。

原图、区域坐标和任务卡冻结并计算哈希。所有方法使用同一任务目标。评价区域不能根据某个方法的结果再挑选。

## 4. 无 GT 评价协议：对齐 restoration_candidates_v1 v1.1

### 4.1 来源、版本与复用边界

主规格为用户指定分支 `docs/restoration-candidates-judge-plan-20261114` 下的 `docs/restoration_candidates_v1/IMPLEMENTATION_PLAN_V1_1.md`，2026-11-17修订；本次读取文件的Git blob SHA为 `655749d1f02f305a94733cf31032f638c62e7ee5`。该文件是待实现的设计与验收合同，不是已完成代码或效果证据。

复用主规格§7–§8的评价语义、§10的生成／选择分离和Judge消融。不直接照搬旧Qwen参数、优先x4、有GT终审、固定四候选及10+24样本配置。本计划首轮仍为H3、restoration_x1、无GT及最多三候选；统一用Pass@K命名。若改为四候选，必须另版调整生成和Judge预算，不能免费增加一张。

评价路径固定为：**Code Hard Gate → Code Soft Evidence → VLM逐属性Eligibility → 合格集合中的Listwise Best。**

### 4.2 生成前冻结EvaluationContract与用途政策

每图从原LQ和任务要求建立EvaluationContract，包含目标、必需区域／实例、恢复充分性、影调颜色、伪影标准、准确性要求、用途、匿名化和并列处理规则。标准独立于最终生成Prompt；生成器漏写要求不能使评价要求消失。

用途按任务而非按模型结果选择：

- `photo_restoration`：允许自然但无法逐像素验证、且无可见冲突的微纹理；仍标记真实性未知。用户明确要求准确的属性不能因此放宽。
- `information_critical`：关键文字、号码、身份等需要在线允许证据支持；未知不能作为已验证正确交付。没有GT或其他允许的可靠证据时，可能合理地全部unresolved，这不等于Judge失效。

每个关键属性及适用实例冻结 `required_for_acceptance` 和 `verification_requirement`。后者为 `visible_consistency`（无可见冲突）或 `verified_content`（证据实际支持该内容）。影调／颜色是本任务的显式必需检查，但数值色差不是未校准的硬淘汰阈值。

### 4.3 Code硬检查与软证据

Code只能依据确定的文件／执行合同排除候选：不可解码、空输出、声明几何不符、源图／请求／输出／ROI／测量绑定不一致、stale证据、输入不是冻结LQ、实际Prompt／seed／配置不符等。未知、缺失和失败单独记录，不自动通过。

以下默认均为软证据，不提前筛图：clipping、亮度分位数、Lab色度变化、edge energy、输入一致性、OCR置信度、人脸embedding、关键点位移及NR-IQA。未知真实退化时，下采样一致性标为proxy。高锐度不证明有效细节，高OCR置信度不证明文字正确。

NR-IQA固定少数版本，例如MUSIQ与TOPIQ-NR；输入SSIM/LPIPS若使用，仅称输入一致性。记录权重、预处理、评价尺寸和适用范围，不能以自动综合分取代资格判定。

每条测量绑定源图、候选、ROI、几何及方法版本；值缺失用null，状态用measured/missing/failed/stale/not_applicable。缺失不等于零或通过。

### 4.4 冻结证据包与ReviewPlan

Judge看独立的LQ整图、匿名候选整图、同位置和尺度的目标／保护ROI及必要上下文，不只看缩水拼图。隐藏Prompt、模型名、seed、策略、离线标签和其他Judge结论。

ROI优先来自已有检测或只看LQ的人工定位。Planner从C0发现新问题时，可以按预先冻结的算法补充观测区域，但必须在替代候选生成前冻结，对同池全部候选使用相同区域；不能追着位移后的输出改框掩盖结构损伤。离线主终点ROI仍使用生成前冻结任务卡。

ReviewPlan在首次Judge调用前冻结，列出每个候选、必需属性、适用实例、整图检查、分包、实际传输图像哈希、匿名顺序、聚合及调用预算。源规格单包默认最多6个主ROI，这是包容量，不是允许漏评的重要实例上限。

超限按预注册规则分包，不删掉重要人物／招牌／背景。预算或上下文容不下必需评审时返回undetermined/unresolved，而非只写coverage_incomplete后继续交付。格式修复和unknown请求均按主规格计入分类和总额度。

### 4.5 逐属性资格判定

逐属性记录 `content_state∈{supported,no_visible_conflict,conflict,unverifiable}` 与 `coverage∈{complete,missing,failed}`；整图记录 `restoration∈{insufficient,adequate,strong,uncertain}` 和 `artifact_severity∈{none,minor,major,uncertain}`。同时保留证据引用、限制及任务对应的影调／颜色判断。

| 必需属性的证据 | visible_consistency | verified_content |
|---|---|---|
| missing或failed | undetermined | undetermined |
| 已确认的关键内容冲突 | ineligible | ineligible |
| supported且证据适用 | 该项通过 | 该项通过 |
| no_visible_conflict | 该项通过，真实性未知 | undetermined |
| unverifiable | 仅photo_restoration预先允许的属性可通过并标未知，其余undetermined | undetermined |

内容冲突必须有原图／ROI／已确认属性依据；无依据的指控不能成为硬否决。逐属性缺项补记missing，不能自动填supported；候选级“整体不错”不能覆盖关键号码未知或必需ROI缺评。

候选资格为 `eligible/ineligible/undetermined`：存在确定拒绝项则ineligible；无确定拒绝项但有必需未知或缺评则undetermined；全部必需项通过且恢复充分、无严重伪影才eligible。关键争议未解决时不通过重复投票消除未知。

### 4.6 合格集合优选与输出状态

仅在eligible集合中比较恢复充分性、细节自然度、影调颜色、整图协调和用途价值，允许并列偏好组。并列首组包含C0时保留C0，否则按生成前冻结tie_order。非候选池没有C0时使用同一预先定义的并列规则。

前两名有实质争议时，在预留预算内最多一次二选一复核并交换匿名顺序。离线人工成对盲评仍随机左右；在线争议复核与离线评价不是同一项实验。

输出分别记录：best_available_id、eligible_ids、preference_groups、best_candidate、content_verification、reason，以及selected/baseline_retained/unresolved/judge_failed。best_available可以不合格，只供审计；无eligible则best_candidate与selected_output为null。Judge解析失败不能偷偷改用NR分数选图。

### 4.7 J0/J1/J2：固定池隔离评价机制

| 版本 | 输入与组织 | 要验证的贡献 |
|---|---|---|
| J0 | 单VLM；匿名整图和同坐标ROI，无Code软数值 | 视觉Judge基线 |
| J1 | 与J0相同图片、顺序、模型和政策，加绑定软证据 | Code证据的增益；首轮默认 |
| J2 | 人物、文字、整图技术、日常观看四视角＋终审 | 额外角色与调用预算下的系统收益；可选 |

J0/J1在同一冻结候选池离线运行，不重新生成。生成策略比较A/B始终用同一J1。J2不是默认上线项；同模型多角色不等于统计独立，不能简单平均分数。

若声称角色分工有独立贡献，增加预算匹配的通用多次评审对照，匹配模型、图片覆盖、Code证据、资格政策、分类调用上限和总输出token限额，披露实际输入token、时间及费用差异。否则仅报告J2系统收益。

单包J0/J1各1次primary，最多1次dispute与1次format_repair，总上限各3次；单包J2默认4次专家primary＋1次终审＋最多1次争议＋1次格式修复，总上限7次。不适用专家可跳过，但空余预算不自动用于探索。多包另行预注册预算，格式修复全variant最多一次，而非每包一次。

### 4.8 独立人工参考评价：替代有GT Oracle，不替代缺失真值

两名人工评审在不知道在线Judge结果和方法名时独立评价，关键分歧由第三人核查；图像证据不足时保留undetermined，不以多数票制造真实性。第三人不必对全部样本复评，预算按最坏上限可预留三人工作量。

复用相同EvaluationContract、逐属性状态及用途政策，但人工不读Judge结论。先按正常观看尺寸评可用性，再看LQ和同尺度ROI核查可见冲突与细节，无法看GT时明确省去GT终审。

在资格之外，独立记录相对LQ的细节改善 I：−2明显变差、−1变差、0无明显改善、+1改善、+2明显改善。保留原计划F（内容）、T（影调颜色）、A（伪影）和UQ（不可核验风险）作为展示与分析字段，不再以这几个总分或多数票直接覆盖逐属性资格。

原LQ或几乎不改的输出不能因内容保持而自动获得恢复成功；核心任务恢复不足为ineligible。自然微纹理可在photo_restoration下合格，但其真实正确性不因此被验证。

### 4.9 指标与分母：统一为Human-judged Pass@K

第i个case的硬契约有效集合为U_i；独立人工按用途判定的合格集合为A_i；其中有感知改善I≥+1的集合为A_i+；人工判定并列最佳集合为B_i（A_i内）；在线正式选择为s_i，可为空。B_i不能由在线Judge自己生成。

| 指标 | 定义或分母 |
|---|---|
| Produced / ContractValid coverage | 至少产生输出／至少有硬契约有效输出的case比例；另报候选级计数 |
| Human-judged Pass@K | A_i非空的case比例，K为冻结候选预算上限 |
| Human-judged Improvement@K | A_i+非空的case比例，作为改善覆盖率C+ |
| Selected Pass | s_i属于A_i的case比例，无正式选择计非通过 |
| Selected Improvement | s_i属于A_i+的case比例；作为主成功率S |
| Conditional Selection Success | A_i非空时，s_i属于A_i的比例 |
| Conditional Improvement Selection | A_i+非空时，s_i属于A_i+的比例；与C+对应的Q+ |
| Best-in-pool Agreement | A_i非空时，s_i属于人工并列最佳B_i的比例 |
| Avoidable Unresolved | A_i非空时s_i为空；同时报告基于A_i+的版本 |
| False Reject | 人工合格但被在线排除的候选比例，分母为全部人工合格候选；区分硬检查、ineligible及undetermined来源 |
| False Accept | 正式交付但不在人工合格集合中，分母为正式交付；拆分人工明确不合格与人工未确定，后者不冒称已证实内容错误 |
| Content Error / Coverage Gap | 已确认内容损伤与必需缺评分别报告；列适用实例数和case数 |
| Cost | 图像、Planner、Rewriter、Audit、Judge、工具次数及token、GPU时间、显存、费用 |

严格区分合格覆盖C和改善覆盖C+，以及对应条件选择率。不能用Pass覆盖率乘Improvement选择率来解释S。在同一完整样本和二元定义下S=C+×Q+；若C+=0则Q+为N/A。

自然度／细节／整体使用价值做成对盲评，允许胜、平、负、双失败和无法判断；报告完整计数。10%左右交换和5%同图质量检查不作为新增独立样本。

所有计划输入保持在分母中；失败、无输出、unknown、partial pool、unresolved、judge_failed不静默剔除。返回LQ可作为安全回退，但不是成功恢复。信息关键任务因证据不足导致全池undetermined时，单列intrinsic_unverifiable，与有合格候选却没选出的可避免拒绝分开。

此处所有人工集合仅表示无GT条件下的判断，不称真实性Oracle。主规格中PSNR/SSIM/LPIPS/CER/身份真值等GT终审不在本次使用；输入一致性诊断与无参考质量仍可保留，但不能替代真值。

## 5. 五个必须实验块

### B0：评价是否可用

**目的：**先保证评价能识别明显错误，避免优化一个有偏或不稳定的 Judge。

在 C 的 12 张原 LQ 上制作受控探针：原样输出、轻度模糊、已知色偏、过强锐化光晕、噪声／重复纹理、可读文字或物体的明确改动。探针只是已知编辑操作的检查材料，不构造干净 GT，也不用于证明恢复性能。

两名人工评审先独立标注，第三人处理关键分歧；不足证据保持未确定，再统一歧义和尺度。建议明显破坏探针的人工检出率≥90%、Judge 严重破坏检出率≥90%、原样输出被误判为“明显改善”的比例≤10%，并抽查通过结果。12 图规模很小，这些只是评价流程的工程检查值，不能当作精确可靠性估计。

**停止条件：**明显破坏仍经常被判优、标注分歧集中或 Judge 不能区分无变化与改善时，先修评价流程；不启动方法搜索。

**交付：**任务卡模板、标注规范、探针清单、失败示例和冻结评价版本。

### B1：强简单基线与可观察权衡

**问题：**现有后处理能否已满足影调／颜色约束，并保留感知细节收益？

| 臂 | 输入与处理 | 需要排除的解释 |
|---|---|---|
| R0 | 原 LQ，不处理 | 输出不变也能获得高保真分 |
| R1 | 固定直接恢复指令的 H3 原始输出 | 生成本身是否有可见改善 |
| R2 | R1 + RGB 均值／方差修正 | 简单统计匹配是否足够 |
| R3 | R1 + 多尺度频率融合 | 保留输入低频、引入生成细节能做到什么 |
| R4 | R3 + 有限局部细节补偿 | 简单补偿能否保留细节而不增伪影 |
| R5 | 仅从 LQ 出发的传统细节增强 | 是否实际上无需生成模型 |

R2/R3/R4 必须来自同一份 R1 输出，保持 seed 和生成条件完全相同。R5 不使用生成结果。所有基线参数只在 D 上选定，每个基线最多预声明 8 个参数组合，禁止逐图看 P 输出调参数。

D 用 24 图×2 seeds，P 用 48 图×3 seeds；只需 192 次新的 H3 生成。后处理变体不再消耗 H3 生成，但计入 CPU/GPU 时间和评价工作量。传统方法与 R0 不重复当作多个 seed 的新样本。

评价 R1–R4 的细节—影调约束关系，并对 R5 进行同尺度盲评。展示所有 P 样本或预声明随机样本，不只挑成功图。

**Gate 1（建议工程标准，运行前确认）：**

- 最佳简单方案在 P 上 S≥60%、严重错误率≤5%，且满足实际任务需求：优先固化工程方案；自动搜索可以暂缓。该判定不等于证明 AutoRef 永远无益。
- R1 的可感知改善仅出现在少数图，或主要是新伪影：先检查执行器、分辨率和任务定义，不优化选择器。
- R1 有改善，但 R2–R4 存在稳定约束损失或不能满足需求：进入 B2。
- 区间很宽或评分分歧大：补数据或修评价，结论为“不确定”，不强行通过。

### B2：固定执行器下，Harness 是否存在空间

冻结 H3 权重、推理实现、尺寸和原生采样配置。主实验不切换模型、不新增学习模块。各臂的后处理集合完全相同；若加入 R3 等后处理，应建立独立的“允许后处理”分支，不能与“纯调用策略”混报。

| 臂 | 调用数上限／根 seed | 策略 |
|---|---:|---|
| P0 | 1 | 原 HarnessIR；不可运行时先补齐并固定，不用 R1 冒名替代 |
| P1 | 1 | 人工优化 Prompt／Evidence |
| P2 | 3 | P1 同提示、三个不同候选 seed，统一选择器 |
| P3 | 3 | 三种预声明互补指令、匹配候选 seed，统一选择器，无反馈 |
| P4 | 3 | 两个互补候选，再依据缺陷提出第三个候选；统一选择器 |

所有候选从原 LQ 生成。P2–P4 使用相同候选数、同一J1、同一逐属性资格政策和最终评价；J0/J1在固定池上另做离线消融。P3 与 P4 的主要区别是第三个候选是否利用失败反馈。P0/P1 作为单次能力对照，不能与三次策略比较后就声称机制优势。

D 的 24 图和 P 的 48 图各用 3 个根 seed 重复完整策略；每个根 seed 内的候选 seed 另行派生。三次完整策略重复与单策略内三张候选是不同层级。匹配 seed 不能保证不同提示有完全相同随机轨迹，但应冻结相同 seed 规则。

生成预算上限：(24+48)×3×(1+1+3+3+3)=2,376。只在输入、Prompt、参数和生成记录完全相同的情况下复用已有结果，不能假定所有原始输出均可复用。

**覆盖率与选择率：**

- 人工判定覆盖率 C：候选池中至少有一个合格改善结果的比例（Human-judged Improvement@K，记C+；普通合格覆盖C另报）。
- 条件选择率 Q：候选池有合格改善结果时，在线J1实际选中合格改善结果的比例（记Q+）；普通合格条件选择率另报。
- 候选池可用但被拒绝的比例，及全池不合格时错误接受的比例。
- 最终改善成功率 S 与 C+−S 的差距；人工覆盖只是可观察标准下的可达表现，不能称 GT oracle。

候选失败、判断不确定、超时等按固定规则处理。C+=0 时 Q+ 不可估计，报 N/A，不填零或100%。为可靠估计 C，P 集所有实际候选都需要独立人工标注，不能只标选中图。D 可用 Judge 加人工审计支持设计，不据此对外报告人工覆盖率。

**Gate 2：**

- P3/P4 相对 P2 的 S 提升达到建议最小实际收益10个百分点、方向在大部分内容层和至少2/3根 seed一致，且严重错误无明显增加：有理由研究结构化 Harness 优化；区间不确定时扩大验证而不是称已证实。
- 改善覆盖C+较高（建议≥60%）但对应Q+较低（建议<80%）：先改选择／拒绝机制，不优先增加生成策略复杂度。
- 改善覆盖C+持续很低（建议<30%）：优先检查任务与执行器能力；不进入全面自动搜索。
- 仅 P2 有收益而 P3/P4 不优于 P2：支持采样与选择，不支持复杂反馈机制。
- 以上阈值都是本项目的拟议决策值，不能当作领域通用标准。

### B3：AutoRef 式优化是否有额外价值

仅在 Gate 2 显示 Harness 可改变结果后启动。冻结图像执行器、推理模型、评价器和可用操作集合。第一版纯 Harness 搜索只允许：证据取舍、指令结构、风险约束、候选生成和定向修订；J1、用途政策、资格判据和Listwise/tie规则固定，不纳入本轮搜索。禁止修改评价规则、访问 V/T、替换模型、加入未授权工具或训练参数。

| 系统 | 定义 | 公平性 |
|---|---|---|
| M | B2 开发得到的人工最优冻结策略 | 披露全部人工试验和开发成本；不宣称人工成本为零 |
| A-Prompt | 只搜索最终指令组织，其余流程固定 | 与 A-Full 使用同一初始策略、搜索任务和预算上限 |
| A-Full | AutoRef 式受限完整 Harness 搜索 | 与 A-Prompt 相同 Proposer、评价器和资源约束 |

每个搜索臂：2轮，每轮4候选，保留2个；每候选跑 D24+V24，每图最多3次生成，搜索筛选先用1个根 seed。D 的图、分数、解释和轨迹允许进入历史，V 仅由隔离评测进程排名，Proposer 只知道哪两个候选存活。保留所有失败和淘汰候选。

每个搜索臂的最大图像预算为2×4×48×3=1,152；两个搜索臂合计2,304。增加每轮代码有效性、禁止访问检查和完整成本日志，但这些执行器检查不等于视觉效果评价。

两臂各保留2个最终候选，共4个，在 V24 上以3个预声明根 seed 复核，预算4×24×3×3=864，按冻结规则各选一个；人工策略在 V 上以同样3根 seed评估，另计24×3×3=216。V 的复核图和分数不再回传 Proposer。

冻结搜索轮数、代码修复预算及回退规则。建议每候选最多2次语法／接口修复；不得把修复变成免费新增策略。图像上限、推理模型 token／调用上限、总GPU时间与总费用同时记录，达到任一硬上限即停止。

**Gate 3 的内部条件：**搜索候选合法、完成预算记账、V上有可用方案即可进入封存测试；V 上领先只用于筛选，不作为自动优化有效的最终结论。A-Full 不优于 A-Prompt 时优先保留简单方案。

### B4：封存测试与最终决策

T 的120个场景、3个根 seed，冻结后一次运行：

| 系统 | 每根 seed 调用上限 |
|---|---:|
| R1：直接 H3恢复 | 1 |
| R*：B1 最佳简单方案 | 1，若为传统方法则0 |
| M：人工最优 Harness | 3 |
| A-Prompt：指令自动搜索 | 3 |
| A-Full：完整 Harness 自动搜索 | 3 |

最大预算120×3×11=3,960。R*若为 R1 后处理并满足完全相同运行条件，可复用 R1 图像，但预算表先按独立运行上限估计。部署存在提前停止时照实报告实际成本；离线覆盖分析保留的额外候选也必须记账。

主终点为Selected Improvement S，另报Selected Pass和Human-judged Improvement@K；主对比为 A-Full−M 和 A-Full−A-Prompt，两项主比较预先声明并进行多重比较校正，例如 Holm。工程目标建议 S 提升至少10个百分点；统计证据要求校正后的区间或检验支持正向改善。

严重错误采用非劣约束：建议风险差的单侧95%上界不超过+5个百分点；该容忍度须在运行前按实际用途确认，不适用于高风险业务的默认承诺。若样本不足以证明非劣，结论为未确定，不能用“没显著差异”冒充同样安全。

120场景只是预算起点。利用 P 的场景级配对差异，在打开 T 结果前做功效／精度规划，必要时预先扩大 T，并更新预算。3 seeds和3标注者不将120场景变成1080个独立样本。即使120场景未见严重错误，也不足以证明风险低于1%。

**最终判定：**

- A-Full 稳定优于 M 与 A-Prompt，风险约束成立：支持在该任务和执行器上采用 AutoRef 式优化。
- 仅优于直接恢复，不优于 M：支持 Harness 的价值，不支持自动优化额外价值。
- A-Prompt 与 A-Full 接近：优先采用更简单的 Prompt 搜索，不主张完整流程必要。
- 平均分改善但内容错误增加：不通过当前保真目标。
- 搜索集改善、T不改善：考虑过拟合或评价器利用，不重开T反复调试；下一轮需要新的封存集。

| 里程碑 | 进入条件 | 最大新增生成 | 交付与决策 |

此预算不含合法技术故障重跑、可选跨模型实验或新的数据；这些必须另记账并设上限。缓存复用只降低实际成本，不改变对照和分母。

先用B1前6张测量真实的每次生成耗时 t_g、每次VLM请求耗时、显存和评价吞吐。图像GPU成本按各方法实际生成分辨率、步数、NFE与设备分别估计，不能用调用次数假装相同算力。若以单卡每次耗时计算，GPU小时约为调用数×t_g/3600；多卡需乘卡数，不能直接当成墙钟小时。

人工评价不能忽略：P集B2的全部候选为48×3×11=1,584张，先双人共3,168份，若每张均需第三人复核则上限4,752份；T最终输出为120×3×5=1,800张，先双人共3,600份，含全量第三人复核上限5,400份。T的两项主成对比较先双人120×3×2×2=1,440份，含全量第三人复核上限2,160份比较，质量控制重复再加约15%。这些不含B0/B1标注和争议复核。

先用20项实测标注耗时，再据公式排期。预算不足时可在运行前减少某阶段根 seed 或缩小范围，并降低稳定性主张；不能只挑“有意思”的图标注后仍声称总体覆盖率。

## 8. 可选扩展与明确暂缓的实验

- 跨模型迁移：仅当H3上的Gate成立，再将冻结策略迁移到Qwen与FLUX。每模型建议48个独立场景，3根seed，比较直接恢复、人工适配和冻结自动策略，上限48×3×(1+3+3)=1,008次／模型。接口Profile允许预先定义，不能看目标结果后免费调参；零样本与专属适配分开。
- 搜索机制：等预算随机搜索可用于检验beam或coding-agent机制的必要性；若只主张使用AutoRef框架有效，可列为补充，不宣称自身改进了搜索算法。
- 删除研究：候选多样性、反馈和成对选择先由B2隔离，避免重新铺巨大矩阵。
- 暂缓训练／LoRA、无预算无限重试、同时加入多个专用恢复器、把无参考分数最大化作为唯一目标。
