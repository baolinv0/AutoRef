# 借鉴 AutoRef 改进 HarnessIR：跨模型适配方案与研究计划

日期：2026-11-18  
用途：导师讨论材料  
阶段：方案论证，尚未实施本次改造或开展新实验

## 讨论摘要

本项目希望回答：**在不微调图像模型的情况下，能否通过优化 HarnessIR 的控制流程，使其稳定适配不同的开放权重图像模型，并改善图像恢复效果与内容保真？**

拟采用“共享恢复目标＋模型专属适配＋离线 Harness 优化”。先将恢复需求表达成模型无关的结构化目标，再为不同模型编译指令、配置执行参数，在有限预算内完成候选生成、失败检查和定向补救。

借鉴 AutoRef 的重点是将 Harness 作为优化对象，以及分离改进反馈与候选筛选。最终验证：收益是否超过人工适配和等预算独立采样，以及共享机制是否能够迁移到未参与优化的模型。

## 一、项目背景

### 1. HarnessIR 的任务与流程

HarnessIR 面向真实低质量图像恢复。通过多模态模型诊断退化、按需调用辅助工具获取证据、组织恢复指令，再由一个图像模型执行恢复。结果不合格时，根据反馈改写指令，并从原始低质量图像重新生成。

**原始低质图 → 诊断 → 按需证据 → 指令组织 → 图像执行器 → 独立验证 → 接受或从原图重试。**

辅助工具为恢复决策提供证据，图像执行器承担实际恢复。本次方案保留这一基本组织方式。

### 2. 跨模型扩展需求

首批讨论对象为 Qwen-Image-2.1、MiniMax-H3-Image、FLUX.3 Image Klein。这里明确采用图像版本；视频版 H3、FLUX Klein Base、蒸馏版及不同量化版本，应分别记录配置身份。

困难在于：**模型接口可以统一，但不同模型理解和执行恢复指令的方式并不一致。**提示组织、采样参数、分辨率处理及候选选择都会影响结果。

### 3. 现有工程基础

仓库并存上游 `harness/` 和本地 Manual Wizard 的 `engine/` 两条通路。本地 Controller 已有状态机、资产隔离、预算、回执和从原图重试等基础。

建议以本地 Controller 为工程承载，复用上游诊断和恢复逻辑，两条入口共享适配定义。此处为拟议整合方向，具体边界仍需实施前确认。

## 二、已有观察与问题定义

### 1. 已有 Qwen 记录

仓库保留的开发实验报告显示：

- 原 Compose 在两套 CFG 配置下均出现 NR-IQA 组均值负收益。
- 压缩重写在 CFG4 的小型开发集上形成候选收益。
- 区域目标版本没有在所有指标上全面优于压缩版本。
- 仅删除部分保守条款，没有恢复原 Compose 的表现。

**证据边界：**这些结论来自仓库保存的生产端报告，本次未独立取得原始图像、逐图分数和运行快照。样本属于开发集，尚不能证明独立测试上的泛化和内容保真收益，也未隔离纯长度效应。

因此，不能得出“所有模型都应该使用短提示”等普遍结论。

### 2. 需要解决的问题

| 问题 | 具体表现 | 改进需求 |
|---|---|---|
| 指令策略难以迁移 | 模型对提示结构、场景描述和保持约束的响应不同 | 分离恢复目标与模型专属表达 |
| 接口适配不等于能力适配 | 能调用 API，不代表参数、尺寸和恢复策略合理 | 建立可追溯的能力与配置档案 |
| 单一质量分数可能误导 | 更亮、更锐或更美观的输出可能改变真实内容 | 同时检查退化去除、保真和严重错误 |

核心研究问题：

> 如何将模型无关的恢复需求，转化为适合不同图像模型的执行策略，并在有限计算预算内获得更可靠的恢复结果？

## 三、AutoRef 的启发与迁移边界

AutoRef 将冻结模型周围的控制程序作为优化对象，包含离线 Harness 搜索及搜索得到的单次推理流程。

| 层面 | 可借鉴机制 | 在 HarnessIR 中的用途 |
|---|---|---|
| 离线优化 | 提出多个候选，在独立数据上筛选，保留多个搜索方向 | 优化适配策略，验证后冻结发布 |
| 单次推理 | 生成结构不同的候选，针对具体缺陷修订，优先排除严重错误 | 有预算的恢复、补救与选择 |

反馈任务用于提出改进，独立选择任务用于筛选候选。这种隔离能够降低直接追逐视觉评分的风险，但不能消除反复筛选造成的过拟合，仍需封存测试集。

迁移时需要改变任务目标。AutoRef 研究多参考图生成，HarnessIR 研究忠于输入的恢复。恢复应优先约束身份、已可读文字、物体数量、场景结构和几何关系，所有候选继续从原始低质图生成，避免错误逐轮累积。

**AutoRef 的既有结果不直接证明本方案对上述三个模型的恢复任务有效，收益需要重新验证。**

## 四、提出的技术方案

### 1. 总体架构

采用“共享恢复目标＋模型专属适配＋离线流程优化”，冻结图像模型参数，优先研究推理流程本身的收益。

**原始低质图 → 诊断与证据 → 结构化恢复目标 → 模型专属编译 → 执行与验证 → 接受或定向重试。**

| 组成 | 主要设计 | 目的 |
|---|---|---|
| 共享恢复目标 | 表达退化、区域、保持要求和不确定信息 | 将任务事实与提示习惯分开 |
| 模型专属适配 | 配置提示组织、参数、图像输入和尺寸处理 | 避免同一套指令生硬迁移 |
| 有预算的闭环 | 候选生成、失败检查、定向补救与选择 | 改善困难样本成功率 |
| 离线 Harness 优化 | 开发反馈提出策略，独立数据筛选 | 减少人工反复调提示的局限 |

### 2. 共享恢复目标

中间表示描述“需要改变什么”，至少包含退化及证据、目标区域、必须保留的内容、无法确认的信息以及恢复优先级。

例如，改善夜景人物的可见性，同时保留夜景照明关系。招牌原本不可读时，不指定模型补写某段文字。

### 3. 模型专属适配

每个模型建立独立 Profile，记录 checkpoint、推理实现、量化方式、提示格式、有效采样参数、输入约定、尺寸策略和已知失败范围。

“官方支持”“接口实测通过”“恢复质量实测通过”分别记录，避免将可调用等同于可靠恢复。

| 模型 | 首个适配方向 | 需要验证的重点 |
|---|---|---|
| Qwen-Image-2.1 | 从已有 compact 候选及区域目标表达入手 | CFG 与指令交互、保真和独立样本收益 |
| FLUX.3 Image Klein | 受原图约束的场景式表达及提示扩写 | 扩写是否添加未观察到的内容 |
| MiniMax-H3-Image | 明确原图角色，使用受约束的编辑扩写 | 实际指令、图片编号、真实生成尺寸 |

上述方向是依据官方说明和已有记录提出的起点，不预设某种表达对某个模型一定最优。

只保留一个负责最终扩写的环节，并记录实际送入模型的文字。尺寸处理进入模型 Profile；原生输出、内部生成尺寸与评价用对齐图分别留存。

第一版继续让执行器仅接收原图和文字，Mask、框等空间控制能力作为后续独立扩展验证。

### 4. 有预算的候选恢复

快速档生成一次，通过检查即停止；质量档每张最多三次生成，按失败情况分配预算。

| 候选 | 方式 | 目的 |
|---|---|---|
| A | 默认适配策略 | 建立首个恢复结果 |
| B | 必要时采用互补指令结构或区域目标 | 探索实际策略差异 |
| C | 根据当前最好候选的主要失败定向补救 | 检查具体反馈能否修复问题 |

每个候选从原始低质图重新生成。反馈聚焦失败位置、问题、修正动作及必须保留的属性，不累积越来越长的失败描述。

选择时先检查严重内容错误，再比较退化去除和自然度。存在争议时交换展示顺序做成对比较；证据不足则保留已有候选。

OCR、人脸特征和结构相似度仅作辅助证据。低质输入中的不可读文字不是可靠真值，与 LQ 更相似也不等于恢复得更好。所有候选失败时，明确标记未成功恢复。

### 5. 离线 Harness 优化

第一阶段将搜索限制在可审查的策略定义：证据取舍、指令结构、内容约束、候选生成和停止条件。评价标准、数据划分、GT 隔离和调用记账保持冻结。

先校准原生调用配置，再固定配置优化 Harness，最后小范围验证参数与策略交互。

搜索可从每轮四个候选、保留两个方向开始，先做两轮，依据预算与选择集表现决定是否继续。这是建议起点，不是必须照搬论文的设置。

数据分为反馈集、选择集和封存测试集。同一场景的不同退化版本、裁剪和相邻帧放入同一集合。已有 Qwen 调参样本用于反馈，不再承担独立测试职责。

## 五、改进计划与验证路径

| 阶段 | 工作 | 要回答的问题 |
|---|---|---|
| 第一阶段：可靠基线 | 核实配置，比较直接恢复、原 HarnessIR 和专属指令 | 适配是否改善单次生成 |
| 第二阶段：有限反馈 | 每张最多三次生成，独立采样和定向补救使用同一选择器 | 反馈是否优于增加计算 |
| 第三阶段：优化与迁移 | 离线搜索、独立筛选、留出模型测试 | 自动优化和公共机制是否有效 |

第一步可做 **12 张分层开发图 × 3 个模型 × 3 种指令策略，共 108 次生成**，覆盖夜景、噪声、模糊、压缩及人脸、文字风险。小试仅筛选方向，不承担泛化结论，正式预算另行冻结。

### 必要对照

| 对照 | 验证目标 |
|---|---|
| 模型直接恢复，一次生成 | 原生能力基线 |
| 原 HarnessIR，一次生成 | 原框架适用性 |
| 模型专属编译，一次生成 | 单次适配收益 |
| 专属编译，三次独立采样与统一选择器 | 额外采样收益 |
| 专属编译，最多三次定向候选与同一选择器 | 反馈相对于独立采样的收益 |
| 离线搜索得到的冻结策略 | 自动优化相对于人工适配的收益 |

同时报告退化去除、内容保真、严重错误率、人工盲评、拒绝率和计算成本。有 GT 的样本增加全参考评价，无 GT 的样本不虚构参考真值。

三次调用不代表相同成本，应记录实际耗时、显存、分辨率及前向计算量。失败样本计入整体结果，不能只报告通过样本。

### 跨模型迁移

在两个模型上优化，冻结策略后迁移到第三个模型。允许使用预先定义的接口与能力映射，但不能根据目标模型测试结果继续调策略；零样本迁移与后续专属适配分别报告。

## 六、研究假设、贡献与风险

### 待验证假设

> 将恢复目标与模型执行策略解耦，再通过保真约束下的离线 Harness 优化，可以比统一提示或人工适配，更稳定地改善不同冻结图像模型的恢复表现。

这是一项研究假设，不是已有实验结论。

### 潜在贡献

核心贡献应集中在“模型能力差异下的恢复策略优化机制”及其证据。多模型接口接入是工程基础；能否形成论文贡献，取决于独立测试中的稳定收益、等预算对照及未参与优化模型上的迁移表现。

### 主要风险

| 风险 | 应对与判定 |
|---|---|
| 收益只来自更多采样 | 与等预算独立采样、同一选择器比较 |
| 评分奖励重画 | 单列严重内容错误，结合人工盲评 |
| 过拟合小样本或评分器 | 场景级划分、封存测试、独立评价 |
| 专属分支过多、公共机制弱 | 做留出模型迁移，分析共享部分 |
| 模型自身能力不足 | 记录全候选失败率，明确适用范围，不无限重试 |

## 七、希望与导师讨论的决策

1. **研究主线：**优先强调跨模型适配，还是自动 Harness 优化？前者可作为任务落点，后者可作为方法机制。
2. **首版范围：**是否将优化重点收敛到指令编译与候选选择，先固定诊断、工具和模型参数？
3. **成功标准：**在可接受预算下，怎样的保真改善、恢复收益和迁移表现足以支持主张？
4. **资源安排：**首批模型、分层数据和生成预算如何选择，是否先完成 Qwen 单模型证据闭环？

建议首版验收目标：同一份恢复目标能够可靠驱动三个模型；每个模型都有可追溯配置和失败边界；在相同预算下，专属策略经过保真检查后优于直接恢复。是否进一步微调，在这些条件验证后再判断。
